# HoloWAN 训练数据生成模块设计方案（完整版）

---

## 1. 目标

将已预处理的 HoloWAN 数据（`data/processed/*.parquet`）转换为结构化的训练与测试数据集，支持后续聚类标注与模型训练。  
关键要求：
- **按文件划分**训练集与测试集  
- **单文件内滑动窗口**（不跨文件）  
- **保留所有有效长度窗口**，通过 `is_valid` 字段标记可用性  
- **预留 `state_id=0`** 供标注模块使用  
- **严格路径分层**：入口脚本仅编排流程，核心逻辑下沉至 `simcore`

---

## 2. 输入

- **目录**：`data/processed/`
- **文件**：多个 `.parquet` 文件（如 `campus.parquet`, `lab.parquet`）
- **每文件结构**：
  - 12 列：`raw_delay_up`, `raw_loss_up`, ..., `norm_delay_up`, `norm_loss_up`, ...
  - 行：时间序列点（按原始日志顺序）
- **前提**：已通过 `scripts/preprocess_holowan_logs.py` 生成

---

## 3. 输出

### 3.1 文件路径
- **训练集**：`data/datasets/train.parquet`
- **测试集**：`data/datasets/test.parquet`

### 3.2 每行字段（共 16 列）

| 字段 | 类型 | 说明 |
|------|------|------|
| `window_id` | string | `{source_file_stem}_idx{start}`（唯一ID） |
| `source_file` | string | 原始 Parquet 文件名 |
| `start_index` | int64 | 在原文件中的起始行索引 |
| `state_id` | int32 | **默认 0**，后续由标注模块更新 |
| `is_valid` | bool | **是否通过清洗规则**（True=可用） |
| `raw_delay_up` | list[float64] (len=100) | 原始上行延迟序列 |
| `raw_loss_up` | list[float64] (len=100) | 原始上行丢包率 |
| `raw_bw_up` | list[float64] (len=100) | 原始上行带宽 |
| `raw_delay_down` | list[float64] (len=100) | 原始下行延迟序列 |
| `raw_loss_down` | list[float64] (len=100) | 原始下行丢包率 |
| `raw_bw_down` | list[float64] (len=100) | 原始下行带宽 |
| `norm_delay_up` | list[float64] (len=100) | 归一化上行延迟 |
| `norm_loss_up` | list[float64] (len=100) | 归一化上行丢包率 |
| `norm_bw_up` | list[float64] (len=100) | 归一化上行带宽 |
| `norm_delay_down` | list[float64] (len=100) | 归一化下行延迟 |
| `norm_loss_down` | list[float64] (len=100) | 归一化下行丢包率 |
| `norm_bw_down` | list[float64] (len=100) | 归一化下行带宽 |

> ✅ 所有窗口长度严格为 100，尾部不足者不生成  
> ✅ 所有候选窗口均保留，用 `is_valid` 实现“软删除”

---

## 4. 核心逻辑

### 4.1 窗口生成规则
- **窗口长度**：100 行
- **步长**：50 行（50% 重叠）
- **作用域**：**严格限定在单个 `.parquet` 文件内部**，绝不跨文件拼接
- **尾部处理**：若 `start_index + 100 > file_length` → 跳过（不生成窗口）

### 4.2 清洗与 `is_valid` 判定
对每个生成的窗口，检查以下条件（基于 `raw_*` 字段）：

| 条件 | 若满足 → `is_valid = False` |
|------|----------------------------|
| **高延迟** | 存在 `raw_delay_up > 2000` 或 `raw_delay_down > 2000`（ms） |
| **恒定延迟** | 上行或下行存在 **连续 ≥10 个周期** 的延迟值完全相等 |

> 🔍 未违反任一条件 → `is_valid = True`  
> 📌 **窗口始终被保存**，仅通过 `is_valid` 标记质量

### 4.3 训练/测试划分策略
- 所有 `.parquet` 文件按**字母序排序**
- **最后一个文件 → 测试集**
- **其余所有文件 → 训练集**

> ✅ 模拟“历史数据训练，新场景测试”的真实部署逻辑

## 5. 新增文件与职责

### 5.1 入口脚本（仅流程编排）
| 文件 | 路径 | 职责 |
|------|------|------|
| 数据集生成入口 | `scripts/generate_training_dataset.py` | 命令行 main 函数，调用 `train_test_splitter.generate_datasets()`，打印统计日志 |

> 📌 **无任何业务逻辑**，仅为胶水代码

### 5.2 核心实现（全部在 `simcore/` 下）

| 功能 | 文件路径 | 职责 |
|------|--------|------|
| **窗口提取与验证** | `src/netfaker/simcore/dataset/window_extractor.py` | 对单文件执行滑动窗口，计算 `is_valid`，返回窗口列表 |
| **训练/测试划分** | `src/netfaker/simcore/dataset/train_test_splitter.py` | 扫描文件、排序、分配角色、聚合窗口、添加元数据（`window_id`, `state_id=0`） |
| **数据集持久化** | `src/netfaker/simcore/io/dataset_saver.py` | 将样本列表转为 DataFrame 并保存为 Parquet |

> ✅ **共新增 4 个文件**  
> ✅ **所有核心逻辑封装在 `simcore/`，可独立测试与复用**

## 7. 后续流程支持

| 场景 | 操作 |
|------|------|
| **初始训练** | 加载后过滤 `df = df[df.is_valid]` |
| **标注模块** | 更新 `state_id` 字段（可选择仅标注 `is_valid=True`） |
| **标注后删减** | 将部分样本 `is_valid` 设为 `False`（软删除，无需重跑） |
| **异常分析** | 检查 `is_valid=False` 的窗口分布与模式 |

---

## 8. 设计优势

| 优势 | 说明 |
|------|------|
| **路径清晰** | `scripts/` 仅为入口，逻辑全在 `simcore/` |
| **数据完整** | 无物理丢弃，支持回溯与审计 |
| **灵活筛选** | `is_valid` 支持动态调整可用集 |
| **标注就绪** | `state_id=0` 提供标准接口 |
| **场景真实** | 按文件划分，避免数据泄露 |
| **工程规范** | 符合分层架构，便于测试与维护 |
