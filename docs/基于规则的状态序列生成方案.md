# HoloWAN 基于规则的状态序列生成方案（完整设计文档）

**版本**：1.0  
**最后更新**：2026 年 1 月 22 日  
**适用项目**：HoloWAN 网络状态仿真系统  

---

## 1. 目标

基于已通过 GMM 聚类标注的窗口数据集（`train_with_state.parquet`），根据用户提供的**状态-时长模板**，自动合成符合指定网络状态序列的仿真流量，并输出为标准 `.txt` 文件，供 HoloWAN Recorder 或回放系统使用。

---

## 2. 前提条件

| 依赖项 | 说明 |
|--------|------|
| ✅ **已标注窗口数据** | `data/clusters/train_with_state.parquet`，包含以下字段： - `state_id`（整数，如 0, 3） - `raw_delay_up/down`（list[float], len=100） - `raw_loss_up/down`（list[int], 0/1, len=100） - `raw_bw_up/down`（list[float], Mbps, len=100） |
| ✅ **窗口时长** | 固定为 **10 秒**，采样率 **10 Hz**（每窗口 100 个时间点） |
| ✅ **HoloWANFile 类** | 已实现 `_add_data()` 和 `write_to_file()` 方法，支持 6 通道写入 |

---

## 3. 输入规范

用户提供一个 **状态序列模板**，格式为 JSON 兼容的列表：

```python
[
  {"type": "s0", "duration": 10},
  {"type": "s3", "duration": 20},
  {"type": "s1", "duration": 10}
]
```

### 字段定义：
| 字段 | 类型 | 约束 |
|------|------|------|
| `type` | string | 必须为 `"s{N}"` 格式，`N` 为非负整数，对应 `state_id = N` |
| `duration` | integer | 单位：秒；必须是 **10 的正整数倍**（≥10） |

> ⚠️ **校验失败将抛出 `ValueError`**

---

## 4. 处理流程

### 4.1 模板解析
- 遍历模板项，提取 `(state_id, duration)`
- 计算所需窗口数：`n_windows = duration // 10`
- 示例：`{"type": "s3", "duration": 20}` → 需 **2 个 `state_id=3` 的窗口**

### 4.2 窗口抽样
- 从 `train_with_state.parquet` 加载数据
- 按 `state_id` 建立索引映射：`state_id → [window_ids]`
- 对每个 `state_id`，**有放回随机抽取**所需数量的窗口（避免因样本不足失败）

### 4.3 数据展开与转换
对每个抽中的窗口，按时间步 `t = 0 … 99` 提取 6 通道数据：

| 通道 | 来源字段 | 转换逻辑 |
|------|--------|--------|
| 上行延迟 (UL Delay) | `raw_delay_up[t]` | 直接使用（单位：ms） |
| 上行丢包 (UL Loss) | `raw_loss_up[t]` | `float(value) * 100.0`（转为百分比） |
| 上行带宽 (UL BW) | `raw_bw_up[t]` | 直接使用（单位：Mbps） |
| 下行延迟 (DL Delay) | `raw_delay_down[t]` | 直接使用（单位：ms） |
| 下行丢包 (DL Loss) | `raw_loss_down[t]` | `float(value) * 100.0`（转为百分比） |
| 下行带宽 (DL BW) | `raw_bw_down[t]` | 直接使用（单位：Mbps） |

> 🔸 **关键**：丢包标记 `0/1` 必须转换为百分比（`0 → 0.0`, `1 → 100.0`）

### 4.4 写入 HoloWANFile
- 创建 `HoloWANFile` 实例，配置如下：
  ```python
  HoloWANFile(
      operator="Synthetic",
      test_name="rule_based_{timestamp}",
      interval_sec=0.1,
      switch="1,1,0,1,1,0"   # ← 默认配置（带宽通道关闭）
  )
  ```
- **逐点调用 `_add_data()`** 添加所有时间点
- 调用 `write_to_file(output_path)` 保存

> 📌 **默认开关配置为 `"1,1,0,1,1,0"`**（即启用 delay + loss，**禁用 bandwidth**），与当前项目设置一致。若需启用带宽，需显式修改 `switch` 参数。

---

## 5. 输出规范

| 产物 | 说明 |
|------|------|
| **仿真文件** | `.txt` 格式，路径由用户指定 - 文件头包含 `operator`, `test_name`, `interval`, `switch` - 数据行：每行 6 列（UL/DL: delay, loss%, bw） - 总行数 = 总秒数 × 10 |
| **日志信息** | 控制台输出： - 模板解析结果 - 各状态抽样窗口数 - 输出路径与总时长 |

---

## 6. 错误处理

| 错误场景 | 处理方式 |
|--------|--------|
| `type` 格式非法 | `ValueError("Invalid type format: expected 's{int}'")` |
| `duration` 非 10 倍数 | `ValueError("Duration must be a positive multiple of 10 seconds")` |
| 请求的 `state_id` 不存在 | `ValueError("No windows available for state_id={X}")` |
| 窗口数据长度 ≠ 100 | `AssertionError("Window data length mismatch")` |

## 7. 模块设计

| 组件 | 路径 | 职责 |
|------|------|------|
| **规则解析器** | `src/netfaker/simcore/synthesizer/rule_parser.py` | 模板校验与转换 |
| **窗口采样器** | `src/netfaker/simcore/synthesizer/window_sampler.py` | 加载 Parquet，按 `state_id` 抽样 |
| **序列合成器** | `src/netfaker/simcore/synthesizer/rule_synthesizer.py` | 数据转换、调用 `HoloWANFile` |
| **入口脚本** | `scripts/generate_by_rule.py` | CLI 接口（支持 JSON 模板输入） |

---

## 8. 使用示例

### Python API
```python
from netfaker.simcore.synthesizer import RuleSynthesizer

template = [
    {"type": "s0", "duration": 10},
    {"type": "s3", "duration": 20}
]

synth = RuleSynthesizer(window_pool_path="data/clusters/train_with_state.parquet")
synth.generate(template, output_path="output/rule_seq_01.txt", seed=42)
```

### 命令行
```bash
uv run python scripts/generate_by_rule.py \
  --template '[{"type":"s0","duration":10},{"type":"s3","duration":20}]' \
  --output output/rule_seq_01.txt
```

---

## 9. 注意事项

- **带宽默认关闭**：因 `switch="1,1,0,1,1,0"`，输出文件中带宽列为 `0.0`，即使窗口含带宽数据  
- **可复现性**：支持 `seed` 参数控制随机抽样  
- **窗口复用**：允许同一窗口被多次抽中（有放回抽样）  
- **仅使用训练集**：测试集窗口不参与合成（因其未用于状态定义）
