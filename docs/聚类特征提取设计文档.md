# 聚类特征提取方案（最终版）

> **目标**：为每个 100 点长的网络状态窗口，提取一个 **8 维固定长度特征向量**，用于后续聚类分析。  
> **输入来源**：`data/datasets/train.parquet` 和 `data/datasets/test.parquet` 中的 `norm_delay_*` 和 `norm_loss_*` 字段（但特征计算基于 **原始物理值**，即 `raw_delay_*`, `raw_loss_*`）。  
> **设计原则**：抗长尾、处理稀疏丢包、窗口内独立计算、保留局部语义。

---

## 1. 输入定义（单个窗口）

每个窗口包含两个方向（上行/下行）的时序数据，每方向 100 个采样点：

| 方向 | 延迟序列（单位：ms） | 丢包率序列（范围：[0.0, 1.0]） |
|------|---------------------|------------------------------|
| 上行 | `raw_delay_up[100]` | `raw_loss_up[100]` |
| 下行 | `raw_delay_down[100]` | `raw_loss_down[100]` |

> ✅ 所有值均来自预处理阶段保存的 `raw_*` 字段  
> ✅ 每个窗口独立处理，**不依赖其他窗口或全局统计量**

---

## 2. 特征提取逻辑（每方向 → 8 维）

对**每个方向**（上行 / 下行），独立执行以下步骤，生成一个 **8 维特征向量**。

### 步骤 1：对延迟（RTT）进行 log 变换
```python
delay_log = np.log(delay + 1)   # shape: (100,)
```
- `delay` ∈ {`raw_delay_up`, `raw_delay_down`}
- 目的：压缩长尾分布，使抖动和尾部延迟更具可比性

### 步骤 2：从 `delay_log` 提取 4 个延迟特征

| 特征名 | 计算方式 | 说明 |
|--------|--------|------|
| `delay_log_mean` | `np.mean(delay_log)` | 整体延迟水平（log 空间） |
| `delay_log_std`  | `np.std(delay_log, ddof=1)` | 延迟抖动（稳定性） |
| `delay_log_p95`  | `np.percentile(delay_log, 95)` | 用户感知的尾部卡顿 |
| `delay_log_max`  | `np.max(delay_log)` | 瞬时最差延迟 |

### 步骤 3：从原始丢包率提取 4 个丢包特征

| 特征名 | 计算方式 | 说明 |
|--------|--------|------|
| `has_loss` | `1 if np.any(loss > 0) else 0` | 是否发生过丢包（二值指示） |
| `cond_loss_mean` | `np.mean(loss[loss > 0]) if np.any(loss > 0) else 0.0` | **条件丢包强度**：仅在丢包时刻计算平均，反映严重程度 |
| `loss_ratio` | `np.sum(loss > 0) / 100.0` | 丢包时间占比（突发性度量） |
| `loss_mean` | `np.mean(loss)` | 原始平均丢包率（保留以兼容传统指标） |

> ✅ `loss` ∈ {`raw_loss_up`, `raw_loss_down`}  
> ✅ 所有计算在当前 100 点窗口内完成

---

## 3. 输出结构（单窗口 → 16 维向量）

由于网络状态具有**上下行双向性**，最终特征向量为：

```text
[
  # 上行特征（8维）
  delay_log_mean_up,
  delay_log_std_up,
  delay_log_p95_up,
  delay_log_max_up,
  has_loss_up,
  cond_loss_mean_up,
  loss_ratio_up,
  loss_mean_up,

  # 下行特征（8维）
  delay_log_mean_down,
  delay_log_std_down,
  delay_log_p95_down,
  delay_log_max_down,
  has_loss_down,
  cond_loss_mean_down,
  loss_ratio_down,
  loss_mean_down
]
```

> 🔸 **总维度：16**  
> 🔸 命名统一使用 `_up` / `_down` 后缀，与项目字段规范一致  
> 🔸 顺序固定，便于程序化解析

---

## 4. 实现注意事项

### ✅ 必须遵守
1. **使用 `raw_*` 字段计算特征**  
   - 即使 `norm_*` 已归一化，**特征提取必须基于物理单位原始值**（`raw_delay_*`, `raw_loss_*`）
   - 原因：`log(1 + raw_delay)` 的语义明确；`norm_delay` 是线性变换，无法正确反映长尾

2. **窗口内独立计算**  
   - 不使用全局 min/max/mean
   - 不跨窗口滑动统计

3. **数值安全**  
   - `log(delay + 1)` 避免除零
   - `cond_loss_mean` 在无丢包时显式设为 `0.0`

### ⚠️ 后续建议（聚类前）
- 对输出的 **16 维特征向量** 使用 `RobustScaler`（基于 IQR，抗异常值）
- 可视化前建议用 UMAP 降维（保留局部结构）

> 📌 后续处理建议
> 由于 16 维特征包含不同量纲的统计量（log-延迟 ∈ [0,8]，丢包指标 ∈ [0,1]），在用于聚类或 UMAP 可视化前，必须对整个特征矩阵应用 RobustScaler。
> 这确保各维度对距离计算的贡献均衡，避免延迟特征主导结果而掩盖丢包模式。
