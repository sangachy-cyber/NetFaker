# NetFaker 核心流程与接口规范（详细工程版）

## 一、系统边界：输入与输出

### ✅ 输入（由用户通过 API 提供）
通过 `POST /api/v1/simulate` 提交一个 JSON 请求体，结构如下：

| 字段 | 类型 | 约束 | 示例 |
|------|------|------|------|
| `strategy` | string | 必须为 `"rule"`（当前） | `"rule"` |
| `target_ip` | IP 地址 | IPv4 或 IPv6 | `"192.168.1.100"` |
| `description` | string (可选) | 用户自定义描述 | `"办公网络仿真"` |
| `segments` | 数组 | 非空，至少一个元素 | `[{"type":"s3","duration":60}]` |

其中每个 `segment` 包含：
- `type`: 字符串，格式为 `s{整数}`，如 `s0`, `s5`
- `duration`: 正整数，单位秒，必须是 **10 的倍数**（因窗口粒度为 10 秒）

> 🔹 **所有字段合法性由 FastAPI 在进入业务逻辑前校验完毕**。非法请求直接返回 HTTP 422，不进入仿真流程。

---

### ✅ 输出（系统生成）
1. **任务响应**（立即返回）：
   ```json
   { "task_id": "task_20260122_152000_a1b2c3", "status": "queued" }
   ```

2. **仿真文件**（异步生成）：
   - 路径：`data/outputs/sim_task_20260122_152000_a1b2c3.txt`
   - 格式：标准 HoloWAN Recorder `.txt` 文件
   - 关键头信息：
     ```
     Operator: NetFaker
     Test Name: 办公网络仿真          ← 来自 request.description
     Destination: 192.168.1.100:8081 ← 来自 request.target_ip
     Switch: 1,1,0,1,1,0             ← 默认关闭带宽通道
     Interval(s): 0.1
     ```
   - 数据体：每行 6 个浮点数（上行延迟、上行丢包%、上行带宽、下行延迟、下行丢包%、下行带宽）

3. **任务状态查询**：
   ```json
   {
     "task_id": "...",
     "status": "completed",
     "result": {
       "output_file": "sim_task_xxx.txt"
     }
   }
   ```

## 二、核心模块交互流程

### 流程图：从请求到文件生成

```mermaid
graph TD
    A[Client POST /simulate] --> B{FastAPI 校验}
    B -- 失败 --> C[返回 HTTP 422]
    B -- 成功 --> D[生成 task_id]
    D --> E[提交后台任务]
    E --> F[调用 simcore/generator.generate_simulation]
    F --> G{策略路由}
    G -->|strategy="rule"| H[RuleBasedStrategy.generate]
    H --> I[获取 app.state.window_sampler]
    I --> J[解析 segments → (state_id, n_windows)]
    J --> K[抽样窗口]
    K --> L[拼接时间点 → 构造 HoloWAN 数据]
    L --> M[写入 data/outputs/sim_{task_id}.txt]
    M --> N[更新任务状态为 completed]
```

## 三、关键模块职责与接口

### 1. **Web 层（`app/`）**
- **职责**：协议处理、请求校验、任务调度
- **输入**：HTTP 请求（JSON）
- **输出**：任务 ID / 文件 URL
- **不涉及**：任何仿真逻辑、数据加载、文件格式

> 📌 **关键动作**：  
> - 启动时预加载窗口池 → 存入 `app.state`  
> - 调度时仅传递 `SimulationRequest` 对象给 `simcore`

---

### 2. **仿真核心（`simcore/`）**
- **职责**：根据策略生成合法 HoloWAN 文件
- **输入**：`SimulationRequest`（已校验）、输出路径
- **输出**：符合规范的 `.txt` 文件
- **依赖**：缓存的窗口数据（来自 `app.state`）

#### 核心子流程（规则策略）：
```
1. 解析 segments:
   [{"type":"s3","duration":60}] 
   → [(3, 6)]  // state_id=3, 需要6个10秒窗口

2. 抽样窗口:
   window_sampler.sample(state_id=3, n=6)
   → 返回6个窗口（每个含100个时间点）

3. 构造 HoloWAN 文件头:
   - Destination = request.target_ip + ":8081"
   - Test Name = request.description or 自动生成

4. 填充数据体:
   for each window in sampled_windows:
       for t in 0..99:
           ul_delay = window.raw_delay_up[t]
           ul_loss  = window.raw_loss_up[t] * 100.0  // 转百分比
           dl_delay = window.raw_delay_down[t]
           dl_loss  = window.raw_loss_down[t] * 100.0
           ul_bw = dl_bw = 0.0  // 因 Switch 关闭带宽
           add_row(ul_delay, ul_loss, ul_bw, dl_delay, dl_loss, dl_bw)

5. 写入文件
```

---

### 3. **窗口抽样器（`window_sampler.py`）**
- **初始化**：读取 `data/processed/train_with_state.parquet`
- **内部结构**：构建 `state_id → [row_indices]` 映射
- **抽样行为**：有放回随机抽样，支持 seed 控制
- **性能保障**：Parquet 仅加载一次，后续为内存操作

---

### 4. **文件输出（`holowan_saver.py`）**
- **封装 HoloWAN 格式细节**
- **确保头信息正确**（尤其是 `Destination`）
- **自动处理浮点精度、换行符等**

## 四、错误与异常处理

| 阶段 | 可能错误 | 处理方式 |
|------|--------|--------|
| **API 层** | 字段非法（如 type="x1"） | FastAPI 自动返回 422 |
| **仿真层** | state_id 不存在于窗口池 | 抛出 `SimulationError` → 任务状态设为 `failed` |
| **I/O 层** | 磁盘写满 | 捕获异常 → 任务 `failed`，记录日志 |
| **启动阶段** | Parquet 文件缺失 | 应用启动失败，健康检查暴露 |

> 所有仿真层异常均记录 `task_id`，便于追踪。

## 六、总结：关键契约

| 组件 | 输入 | 输出 | 契约 |
|------|------|------|------|
| **API** | JSON 请求 | task_id / 文件 URL | 输入必须合法，否则 422 |
| **Generator** | strategy + request | 文件路径 | 调用正确策略 |
| **Rule Strategy** | SimulationRequest | .txt 文件 | 文件头含 target_ip 和 description |
| **Window Sampler** | state_id + n | 窗口列表 | 返回合法窗口，否则报错 |
| **HoloWAN Saver** | 元数据 + 数据点 | .txt 文件 | 严格符合 HoloWAN 格式 |

此设计确保 **输入清晰、输出规范、流程可控、扩展简单**，完全适配你当前的目录结构，且具备生产级健壮性。
