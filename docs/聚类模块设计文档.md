# HoloWAN 聚类与状态生成模块设计方案

> **目标**：基于训练集窗口数据，通过聚类定义网络状态（`state_id`），并为测试集分配一致语义的状态标签。  
> **默认策略**：使用 **GMM（高斯混合模型）聚 3 类**，输出概率增强的 `state_id`。  
> **设计原则**：  
> - 聚类仅在训练集执行  
> - 测试集通过模型预测获得 `state_id`  
> - 所有特征处理复用已验证的 16 维提取方案  
> - 架构支持未来无缝接入 KMeans、DBSCAN 等算法

---

## 1. 输入数据

| 文件 | 字段 | 说明 |
|------|------|------|
| `data/datasets/train.parquet` | `raw_delay_up/down[100]`, `raw_loss_up/down[100]`, `is_valid` | 用于定义状态 |
| `data/datasets/test.parquet` | 同上 | 用于映射状态 |

> ✅ 特征提取调用已实现的 `extract_features_from_window()`（见 `feature_extractor.py`）  
> ✅ 输出：每窗口 → 16 维向量（8 上行 + 8 下行）

---

## 2. 整体流程

```mermaid
graph LR
A[Train Parquet] --> B[提取 16D 特征]
B --> C[RobustScaler.fit_transform]
C --> D[GMM 聚类 (n=3)]
D --> E[state_id = cluster_id]
D --> F[state_proba = max(prob)]
G[Test Parquet] --> H[提取 16D 特征]
H --> I[RobustScaler.transform (复用)]
I --> J[GMM.predict → state_id]
I --> K[GMM.predict_proba → state_proba]
E & F --> L[保存 train_with_state.parquet]
J & K --> M[保存 test_with_state.parquet]
C & D.model --> N[保存 scaler + gmm_model.joblib]
```

---

## 3. 核心组件

### 3.1 特征标准化
- **方法**：`RobustScaler`（按 16 列独立缩放）
- **拟合集**：仅训练集
- **保存路径**：`data/clusters/feature_scaler.joblib`

### 3.2 聚类算法：GMM（默认）
- **实现路径**：`src/netfaker/simcore/clustering/clusterers/gmm.py`
- **默认参数**：
  ```python
  {
    "n_components": 3,
    "covariance_type": "full",
    "max_iter": 200,
    "random_state": 42,
    "init_params": "kmeans"
  }
  ```
- **输出**：
  - `cluster_id`: int（0, 1, 2）
  - `cluster_proba`: float（最大后验概率）

### 3.3 状态分配
- **训练集**：`state_id = cluster_id`, `state_proba = max(prob)`
- **测试集**：直接调用 `gmm.predict()` 和 `predict_proba()`

> ✅ **无需额外分类器**：GMM 原生支持新样本预测

## 5. 默认状态语义（初始假设）

| `state_id` | 初始解释（供人工审核参考） |
|-----------|--------------------------|
| 0 | **稳定状态**：低延迟、低抖动、无丢包 |
| 1 | **抖动状态**：中高延迟波动，偶发卡顿 |
| 2 | **异常状态**：高延迟尾部、持续丢包或极端抖动 |

> 🔍 实际语义由数据驱动，可通过 UMAP + 特征均值分析验证并修正

## 7. 使用方式（uv）

```bash
# 默认：GMM 聚 3 类，并为测试集分配 state_id
uv run python scripts/run_clustering.py --algorithm gmm

# 自定义簇数
uv run python scripts/run_clustering.py --algorithm gmm --n-components 4
```

> 🔧 默认自动处理 `is_valid == True` 的窗口  
> 🔧 支持后续扩展 `--algorithm kmeans` / `dbscan`

## 9. 设计优势

| 优势 | 说明 |
|------|------|
| **开箱即用** | 默认 GMM 3 类，符合典型网络场景 |
| **概率增强** | `state_proba` 支持置信度过滤与人工审核 |
| **端到端一致** | train/test 共享同一状态空间 |
| **无数据泄露** | scaler 和 GMM 仅从训练集学习 |
| **可扩展架构** | 新增算法只需实现 `BaseClusterer` |
