# HoloWAN 日志预处理设计方案（完整版）

---

## 1. 目标

对原始 HoloWAN 网络日志（`.txt` 格式）进行标准化预处理，生成结构清晰、语义明确的中间数据，用于后续验证、聚类或建模。  
预处理聚焦于 **延迟（delay）字段的归一化**，同时保留原始值以支持可逆性与人工验证。

---

## 2. 输入规范

- **目录路径**：`data/raw/`
- **文件格式**：纯文本 `.txt`，每行包含六列空格或制表符分隔的数值：
  ```
  delay1 loss1 bw1 delay2 loss2 bw2
  ```
- **解析依赖**：复用项目中已有的 `HoloWANFile` 类（位于 `src/netfaker/simcore/utils/holowan.py`）
- **文件命名**：任意（如 `campus.txt`, `wan_trace.txt`），不包含任务 ID

---

## 3. 字段语义与命名规范

### 3.1 原始字段映射（加载时立即重命名）

| 原始列（来自 HoloWANFile） | 统一新命名 | 含义 |
|--------------------------|-----------|------|
| `delay1` | `delay_up`   | 上行延迟（ms） |
| `loss1`  | `loss_up`    | 上行丢包率（%） |
| `bw1`    | `bw_up`      | 上行带宽（Mbps） |
| `delay2` | `delay_down` | 下行延迟（ms） |
| `loss2`  | `loss_down`  | 下行丢包率（%） |
| `bw2`    | `bw_down`    | 下行带宽（Mbps） |

> ✅ 所有后续处理和输出均使用 `_up` / `_down` 后缀，**禁止出现 `1`/`2` 数字标识**

### 3.2 输出列前缀规范

在最终 Parquet 文件中，所有字段必须带有统一前缀：

| 数据类型 | 前缀 | 示例 |
|--------|-----|------|
| 原始未处理值 | `raw_` | `raw_delay_up`, `raw_bw_down` |
| 预处理后值   | `norm_` | `norm_delay_up`, `norm_bw_down` |

> ✅ 共 12 列（6 原始 + 6 归一化），结构固定，便于程序化解析

---

## 4. 预处理规则

### 4.1 Delay 字段（核心处理）

- **变换步骤**：
  1. 对 `delay_up` 和 `delay_down` 应用 `log(1 + x)`（缓解长尾分布）
  2. 应用 `StandardScaler` 进行标准化（均值为 0，标准差为 1）

- **Scalers 模式（由配置开关控制）**：
  - **共享模式（`shared_delay_scaler=True`）**：  
    将所有 trace 的 `delay_up` 和 `delay_down` **合并为一个整体**，拟合**单一全局 scaler**
  - **独立模式（`shared_delay_scaler=False`）**：  
    分别聚合所有 trace 的 `delay_up` 和 `delay_down`，拟合**两个独立 scaler**（`scaler_up`, `scaler_down`）

> 🔧 该开关在预处理入口处显式指定（如策略参数或脚本配置）

### 4.2 Loss 字段

- `loss_up` / `loss_down` → 仅执行线性缩放：`value / 100.0`  
- **不进行标准化，不保存 scaler**

### 4.3 Bandwidth 字段

- `bw_up` / `bw_down` → **保持原始值不变**，不做任何变换

---

## 5. 输出规范

### 5.1 中间数据文件

- **目录**：`data/processed/`
- **文件名**：与输入文件同名，扩展名改为 `.parquet`  
  （例：`data/raw/campus.txt` → `data/processed/campus.parquet`）
- **内容**：Parquet 格式 DataFrame，含 12 列（`raw_*` + `norm_*`）

### 5.2 全局 Delay Scaler（唯一元数据）

- **文件路径**：`data/processed/global_delay_scaler.joblib`
- **内容结构**：
  - **共享模式**：
    ```python
    {
      "mode": "shared",
      "scaler": StandardScaler 实例
    }
    ```
  - **独立模式**：
    ```python
    {
      "mode": "separate",
      "scaler_up": StandardScaler (for delay_up),
      "scaler_down": StandardScaler (for delay_down)
    }
    ```

> ✅ 所有 trace 使用同一份 scaler，确保归一化一致性  
> ✅ 支持后续新数据推理或反变换

## 6. 代码模块与路径

为避免职责混淆并支持未来扩展，**HoloWAN 相关 I/O 逻辑完全隔离在专用模块中**：

| 功能 | 文件路径 | 职责 |
|------|--------|------|
| **HoloWAN 解析器** | `src/netfaker/simcore/utils/holowan.py` | 提供 `HoloWANFile` 类（**不修改**） |
| **HoloWAN 加载器** | `src/netfaker/simcore/io/holowan_loader.py` | 加载 `.txt` → DataFrame，重命名为 `_up`/`_down` |
| **HoloWAN 预处理器** | `src/netfaker/simcore/preprocessing/holowan_preprocessor.py` | 实现全局统计、归一化、模式开关 |
| **HoloWAN 保存器** | `src/netfaker/simcore/io/holowan_saver.py` | 写入 `.parquet` 和 `global_delay_scaler.joblib` |
| **HoloWAN 预处理入口** | `scripts/preprocess_holowan.py` | 预处理流水线主脚本，提供命令行接口 |

> 🔹 **通用 I/O 文件（如 `data_loader.py`, `result_saver.py`）保留给未来其它数据源使用**（如 PCAP、合成数据、聚类标注集等）

## 8. 关键设计原则

| 原则 | 说明 |
|------|------|
| **复用现有工具** | 直接调用 `HoloWANFile`，零改动 |
| **语义清晰命名** | `_up`/`_down` + `raw_`/`norm_` 前缀 |
| **全局一致性** | 所有 trace 共享同一 scaler（按模式） |
| **可验证性** | 保留原始值，支持人工比对 |
| **可扩展性** | 专用模块命名，为训练/标注数据留出空间 |
| **部署友好** | 无 task_id，无嵌套目录，符合生产部署习惯 |
